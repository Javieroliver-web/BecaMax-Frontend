=== 🔒 SEGUNDA AUDITORÍA DE SEGURIDAD (2026-08-29, más profunda) ===
- [x] CRÍTICO: cualquier usuario registrado podía auto-promocionarse a admin
      (o desbloquearse a sí mismo si estaba bloqueado) llamando directo a la
      API de Supabase (`perfiles.update({rol:'admin'})`), porque la policy
      RLS solo comprobaba dueño de fila, no qué columnas se podían tocar.
      Cerrado con un trigger (`supabase/perfiles_privilege_guard.sql`) que
      exige ser admin para cambiar `rol` o `estado`. Verificado en producción.
- [x] XSS almacenado no autenticado vía `incidencias` (mismo patrón que el de
      system_logs de la primera auditoría, en una tabla que no se había
      tocado): escapado el render en admin-incidencias.html.
- [x] Auto-XSS de amplio alcance vía nombre/avatar del propio usuario en
      auth.js (se ejecutaba en el menú de cabecera de TODAS las páginas).
      Escapado.
- [x] Auto-XSS vía etiquetas de filtros guardados y vía nombre de alerta
      (escapado incompleto en un onclick) en dashboard.js. Corregidos.
- [x] /api/becas devolvía 0 € en todas las becas por leer columnas
      inexistentes (esquema descartado); corregido para leer el `importe`
      JSONB real. Null-safety añadida en app.js/dashboard.js para becas sin
      importe verificado (las de la BDNS).
- [x] Enlaces "Ver beca" no bloqueaban el esquema `javascript:` en URLs de
      fuentes externas (BDNS); añadida validación de esquema (`safeUrl()`).
- [x] CORS devolvía siempre el mismo valor fijo sin comprobar el Origin real
      de la petición; ahora valida de verdad contra FRONTEND_URL.
- [x] `trust proxy` añadido para que el rate-limit detecte bien la IP
      real detrás del proxy de Vercel.
- [x] Rate limiting real con Upstash Redis (persiste entre invocaciones
      serverless, a diferencia del limiter en memoria anterior), con
      fallback automático si no está configurado. Verificado en producción
      (cabecera X-RateLimit-Backend: upstash).
- [x] Permisos de `anon` demasiado amplios en `admin_repair.sql` (system_logs,
      incidencias) y patrones de política RLS obsoletos en `setup.sql`
      (perfiles/filtros_guardados/incidencias) que habrían reabierto el bug
      de "permission denied for table perfiles" si se re-ejecutaban.
      Corregidos para usar `public.is_admin()` de forma consistente.
- [x] Límite de longitud añadido a `incidencias.descripcion`/`tipo` (el
      formulario público no pasa por ningún rate-limit del backend).
